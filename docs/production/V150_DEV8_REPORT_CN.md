# Lost Frequency v1.5.0-dev8：旧关卡纵向重制与 L009 物理路线回归

> 状态：**源码开发候选**。2026-11-07。基线：v1.5.0-dev7（100 个场景文件）。
> 重要：本环境没有可运行的 Godot 4.5.1，也没有 Windows 实机。**尚未完成 Godot GDScript 解析、物理导航、交互、显卡截图、FPS 或 Windows 启动验证**。不得用下列离线测试代替这些证据。

## 交付范围

本轮不增加 Level 编号，针对质量不足的旧关卡重做可探索空间和行为：

1. **L001 / Habitable Zone：维护夹层**：在东侧 `(1,0)` 分块实现两层有效高度；原吊顶抬升至 9.2m；16 级真实楼梯、4.2m 的悬空平台、连接桥、护栏、支撑柱、可手动控制的应急灯、维护记录和专门的截图机位。将原该分块容易干扰楼梯的柱体/灯/管线布局进行局部避让；新建筑是游戏改编探索空间，**没有增加虚构的跨关卡出口**。
2. **L009 / The Suburbs：三层夜间车库**：原本远端的单调实心建筑改为开敞的立体停车空间，增设两段连续楼梯、双层平台、护栏、标线、照明、调查日志。构建器显式隔离原 `end_owner` 出口所在分块，保留 L009→L011 原目的地、原设定的正常十路牌/八次触发条件。
3. **L007 / Thalassophobia：水下声响互动**：给原有管道结构增加必须靠近的打击交互，复用已经存在的 `_strike_pipe()` 驱赶机制；在四段下潜深度的转换点输出气氛/导航字幕；没有虚构新实体或出口。
4. **L001 实体行为**：Smiler 改为在攻击和追逐前进行物理射线视线检测，避免隔墙攻击；排除玩家自身碰撞体；出生候选方向检测壁面，不能找出安全方向时延迟生成。
5. **L009→L011 剧情诊断**：旧机器人会在被挡住时直接跳过导航顶点（假阳性），现在遇到卡阻停下并保留顶点位置、滑动碰撞数量与进度样本。QA 的三路牌进度只在玩家依次**真实走入**每个路牌邻域时更新，出口仍由正常 `ExitTrigger` 决定是否触发。
6. **独立定向引擎测试**：`--suite=l009_route` 从真实 `from_L005` 出生点启动，检测出生点、逐段导航、三次进度递增和 L009→L011 真实出口信号；不手动注入进度、不穿墙、不从远处调用出口。测试结果写入独立 JSON，包括导航进度采样。原多关剧情链保持可运行。

## 离线验证结果（已实际执行）

- `python -m unittest discover -s tests/static -q`：**58/58 通过**，其中新增 10 项 dev8 专项断言。
- `python tools/world_audit.py --fail-on-issues`：100 个场景、235 条出口声明、按清单从 Level 0 可达 43 关、结构问题 0。该数字不代表玩家已验证通行。
- `tools/preflight_dev.py` 的词法扫描逻辑用于遍历 204 个 `.gd` 文件：未发现字符串/括号层面的错误。**该扫描器不是 GDScript 编译器**。
- `tools/production_gate_dev8.py`：**0/100 关取得完整发布验收**。发布门槛不接受 dev7 的旧 QA 当作 dev8 的成功记录。

## 关于 L009 故障的谨慎结论

早期 Godot 日志表明 L009→L011 在 9000 物理帧内未触发，但没有每路牌到达和进度证据，因此**不能凭静态阅读断言原故障已经修复**。本轮已修正 QA 导航误判及路牌进度状态，并提供能识别具体失败步骤的新测试。真实根因仍取决于引擎运行后的导航和碰撞证据。

## Windows 构建限制

若存在 `LostFrequency_v1.5.0-dev8_Windows_x86_64_EXPERIMENTAL.zip`，其 EXE 采用旧 Godot 引擎与离线 PCK 重封装，仅能声明包内资源完整性；**不是 Godot 原生导出，不代表能在 Windows 启动**。正式构建应从源码使用 `EXPORT_DEV8_WINDOWS.ps1`，并补齐 GPU/人工验收。
