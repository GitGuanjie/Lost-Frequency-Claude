## 核心重构：重复使用，但各场景独立着色和定位

新增 `core/world/VerticalArchitecture.gd`。不是视觉占位：用 `GeoKit.slab` 生成各层实心楼板、用 `GeoKit.stairs` 生成有平滑碰撞斜面的实体台阶、为每次上升提供完整的 20 米长梯道空间。每层两组相反方向的上行梯，加上贯穿中央与两侧的长廊，形成两个上楼路径、多个平面换边路径和至少 3 个结构环路。楼板沿两条 x 槽位开洞，梯道顶端接水平实心落脚板；栏杆沿外边与开口边连续布置。普通地面由各关原始世界自身提供，不覆写出生点。

## 自动化 QA 与保留的风险

- `VERIFY_DEV15_OFFLINE.py`：运行本工程的 Python 静态测试、场景文本几何约束、数据结构连通性与 canonical 世界审计。
- `tests/static/test_dev15_vertical_networks.py`：新增独立测试，校验双梯形槽位、上层踏板、L022 三个上层落点、L030 两条高坡道、原始关卡出口 manifest 的 SHA-256。
- `tests/qa_runner.gd --suite=vertical_dev15`：仅 Godot 真引擎内运行，探测新建高层楼板、楼梯槽的**空洞**、斜坡碰撞的射线命中；新建 L030 实体高桥、L022 四层的射线断言。不能偷换为静态图的结果。
- `tools/run_dev15_qa.py`：执行完整导入、模型实例化、登记、旧版场景测试、dev14 和 dev15 物理结构测试及 L009→L011 剧情路径。若缺少 Godot 可执行文件、证据报告、版本对不上、任何 suite 失败则整体**FAIL**。为 dev15 新建的模型 smoke 场景仍要求 **414/414 模型**与 **466/466 摆位**。

当前运行环境中无 Godot 4.5.1 二进制、且不能通过网络下载安装，故**未执行 GDScript 引擎解析、真实角色走上梯段的碰撞／净空／卡点检测，也未运行 Windows EXE**。静态通过的标记不得冒充上述真实引擎验收结果。关卡原版故事路线也未因新增几何而重置验证。

## Windows 引擎验证与实验性导出

安装 Godot **4.5.1**（Windows console executable）、同版 export templates，以及 Python 3 后，在源码根目录 PowerShell：

```powershell
python VERIFY_DEV15_OFFLINE.py
.\RUN_DEV15_QA_WINDOWS.ps1 -GodotExe 'C:\Path\Godot_v4.5.1-stable_win64_console.exe' -Story -Full
.\EXPORT_DEV15_WINDOWS.ps1 -GodotExe 'C:\Path\Godot_v4.5.1-stable_win64_console.exe' -Story -Full
```

第三个命令**只有在 QA 摘要为 PASS 时**才放行导出实验性 `export/windows/LostFrequency_v1.5.0-dev15_EXPERIMENTAL.exe`。导出后仍需人工在 Windows 上验收 9 个改动关卡的实际角色台阶攀爬、左右梯道净宽、上下通道头部净空、边缘跌落防护，原 100 关选关/暂停/恢复、存档和 L009→L011 的真实触发。
